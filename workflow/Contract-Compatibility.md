## Contract notes

- **Workflow record:** Schema v2 is the canonical writable workflow record.
- **Workflow record:** Schema v1 is legacy input only and must migrate before ordinary workflow mutation.
- **Orchestration context:** The current CLI emits context protocol v3 for initialized CLI-managed state.
- **Orchestration context:** Its version is independent from workflow-record schemaVersion.
- **Agent packet:** The packet exposes the wrapped context version separately as contextProtocolVersion.
- **Agent packet:** An uninitialized project uses the same packet protocol with contextProtocolVersion null.
- **Portable agent projection:** AGENT-CONTEXT.json is a read-only generated projection, not a second workflow engine.
- **Portable agent projection:** Its projectionVersion is independent from the executable agent-packet protocol even when both numbers happen to match.
- **GitHub remote command:** The issue-envelope protocol is an independent transport for canonical CLI argv and exact expected branch HEAD.
- **GitHub remote command:** Runtime workflow compatibility is determined by the exact pinned toolkit revision executed by the bridge, not by agent-packet or projection version numbers.

## Version-bump procedure

1. Change only the contract whose externally observable shape or semantics changed.
2. Update `cli/lib/contract-compatibility.mjs` first, including compatibility relationships and migration-only behavior.
3. Update the affected producer/consumer implementation and focused regression tests.
4. Run `node scripts/generate-contract-compatibility.mjs` to refresh this table.
5. Run `npm run validate` before merging.

Do not bump unrelated contracts merely to keep version numbers visually aligned.
